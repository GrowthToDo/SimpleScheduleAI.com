WORD COUNT TARGETS (by content type):

- BOFU comparison/best-of: 3,000–5,000 words
- How-to / tutorial: 2,000–3,000 words
- vs-service MOFU (self-serve vs managed): 1,500–2,500 words (upper end if tool profile includes reviewer quotes)

TONE RULES — strictly enforced:

- No em-dashes (—). Use commas, colons, or rewrite the sentence.
- No --- horizontal rules between sections (AI-tell pattern).
- No AI-generated tone: no "delve into", "dive into", "it's worth noting",
  "in conclusion", "robust", "leverage", "game-changing", "seamless",
  "comprehensive solution", "transformative", "at the end of the day",
  "unlock", "harness".
- Write like a hospital operations veteran talking to a peer. Direct, plain,
  specific. If a sentence could appear in a generic AI blog, rewrite it.
- No unverified claims framed as facts. If you can't link to a source,
  rephrase as an observation.

AEO RULES — every competitor section must be citable:

- Every tool reviewed (including tools being ruled out for CAHs) must follow
  the full structure: 2-3 paragraph description, Best for, Key limitations,
  Verdict, Cost. No brief dismissals.
- Each section must contain at least one specific, documentable claim: a named
  missing feature, a CMS/FLSA compliance gap, a G2/Capterra reviewer quote,
  or a documented implementation timeline. "Tool X is not ideal for CAHs" is
  not citable. "Tool X has no CMS §485.635 audit trail export" is.
- Vague verdicts ("insufficient for CAHs") have no AEO value. Name the exact
  gap that makes it insufficient. AI engines cite specific claims, not opinions.
- Minimum word count per competitor section: 150 words, even for tools being
  ruled out. A short section signals thin research, not editorial confidence.

DIAGRAM RULES:

- NEVER use inline SVG in .md blog posts. SVGs have inherent text-overflow and dark mode
  issues in Markdown files — hardcoded fill colors break dark mode, text nodes overflow bars
  and get extracted as raw concatenated text by some renderers.
- Use Tailwind HTML instead: <div> bar charts with percentage widths, <table> for comparisons.
  Both work in dark mode with dark: variants and never overflow.
- Every diagram needs a descriptive surrounding heading or caption so it is accessible.
- Minimum 2 visual elements (tables or div charts) for BOFU/how-to, minimum 1 for MOFU.
  \*/}
