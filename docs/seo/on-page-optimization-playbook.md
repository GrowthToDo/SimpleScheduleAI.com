# On-Page Optimization Playbook (SimpleScheduleAI)

A repeatable workflow for optimizing an EXISTING page or post that already ranks (typically GSC position 5 to 40) to push it higher and earn AI Overview / AEO citations. This is the "rank-rescue" loop.

Adapted from a generic on-page-optimization prompt (Revenueholic / OpenCraft AI). The house overrides in the section below are what make it ours. This playbook is SUBORDINATE to:

- `.claude/skills/seo-aeo-simplescheduleai.md` (house SEO/AEO rules, especially PART 0)
- `docs/seo/pre-publish-checklist.md` (hard publish gates)

Where anything here conflicts with those two, they win.

## When to use it

- A page or post is ranking but stuck (GSC position 5 to 40) and we want to move it up or earn an AIO citation.
- NOT for writing a brand-new post: for that, run the 3-agent blog pipeline in `CLAUDE.md`. This playbook is the lens for the Research phase when the target already exists.

## Inputs required (do not run without all three)

- Primary keyword.
- Current position (GSC, 7 to 28 day window).
- The page file: an Astro page in `src/pages/` or a post in `src/data/post/`.

If the page or the keyword is unknown, stop and ask.

## Workflow

### Step 0 — Pull the live data (main agent only)

Subagents do NOT get the DataForSEO / GSC / Bing MCP tools. The main agent must pull these and hand the data to any research subagent.

- GSC `get_advanced_search_analytics` (query and page dimensions): current position, impressions, CTR.
- DataForSEO `serp_organic_live_advanced`: the live SERP. Capture the AI Overview, People Also Ask, related searches, and who ranks top 10.
- DataForSEO `dataforseo_labs_google_keyword_overview` + `bulk_keyword_difficulty`: volume, KD, intent.

### Part 1 — SERP landscape

One paragraph: what kind of SERP this is (informational vs commercial), who owns it (gov/.org authority, established vendors, comparison sites, Reddit), the role of the AI Overview and what content types it cites, and the realistic prize. Be honest: on authority-owned SERPs we do not outrank CMS / RuralHealthInfo / symplr; we play for the AIO citation, the long-tail, and the CAH-qualified slice.

### Part 2 — Competitor evaluation (top 3 most instructive)

Pick the 3 most instructive results, usually the #1 authority, the closest analog to us, and the most beatable page. For each: URL, page type, intent, and a 4-criteria table rated strong / adequate / weak with specific evidence:

- Clarity: is there a clean, liftable definition or answer?
- Depth: does it cover the sub-questions?
- Usefulness: does it actually help the reader?
- Presentation: FAQ, tables, scannability?

Plus Strengths and Weaknesses. Focus on what earns the AI Overview citation and what we can realistically match or beat.

### Part 3 — Gap analysis

- Our page's current strengths (cite line numbers).
- Critical gaps table: Gap | Impact (Critical / Medium / Low) | Who has it. Look for: missing clean definition capsule, missing or weak FAQ vs the PAA questions, missing comparison framing, thin title/meta, internal-link gaps, unsourced claims.

### Part 4 — Tiered on-page checklist

Number steps sequentially across all tiers. Each step: Issue / Fix (exact action, with recommended title, meta, FAQ questions, anchor text) / Why.

- P1 Critical: title, meta, H1, the AEO definition capsule (clean, brand-free, liftable, near the top), indexability and canonical.
- P2 Content depth: FAQ answering the live PAA questions (synced into BOTH the rendered FAQ and the FAQ schema object if the page has one), comparison capsule or table, answer-first first sentences under each H2.
- P3 E-E-A-T: founder/operator credibility, a source link on every stat and regulatory claim.
- P4 Technical: internal linking, image alt text, heading hierarchy. NOT schema-stacking (see overrides).
- P5 Refinement: CTA, AI-tone and dash sweep, tighten promotional and redundant prose.

### Part 5 — Internal linking (our site only)

Two tables: links to ADD FROM the page, and published posts that should link TO it. Mandate both topical pillars plus `/how-it-works`. Then a minimum-viable 8 to 10 link list. Ignore any "scrape an external blog" step from generic templates; we link our own pages only.

## House overrides (what makes this OURS, not generic SEO)

1. NO schema-stacking. Schema is auto-generated by the Astro layout. PART 0 of the skill: structured data is not an AIO lever, and FAQ/HowTo rich results are dead. Do not hand-add FAQPage / HowTo / Article JSON-LD as a ranking tactic.
2. Title length is NOT a publish gate. The site template auto-appends the brand to every `<title>` (see `titleTemplate` in `src/config.yaml`). Do not hand-add a brand suffix, it doubles. The H1 stays keyword-first and brand-free by design.
3. CTA model = flat pricing + book-a-call. The free pilot is RETIRED. Never add a `/pilot` link. Use `/how-it-works`, `/pricing`, and the cal.com booking link.
4. Internal links from OUR pages and posts only (`src/pages/`, `src/data/post/`).
5. Two mandatory topical pillars: `/nurse-scheduling-software` and `/critical-access-hospital-scheduling`. These are the hub-and-spoke hubs we are trying to rank, so every spoke links up to both. Also link `/how-it-works` from any service mention, and `/ai-nurse-scheduling`, `/pricing`, `/roi`, and related spoke posts where contextually relevant.
6. All house hard gates apply to any copy you add: no em-dashes or en-dashes anywhere, no AI-tone, dark-mode variants on any table, no fabricated stats (every stat sourced or framed as an estimate), correct CFR sections (Section 485.631 for staffing, Section 485.635 for provision of services).
7. Honest ranking expectations, stated plainly. Do not contort a page (stripping a winnable qualifier, chasing tricks) to chase a head term we cannot win.

## Tooling map

- Position, impressions, CTR: GSC MCP (`get_advanced_search_analytics`).
- SERP, PAA, AI Overview, volume, KD: DataForSEO MCP (`serp_organic_live_advanced`, `dataforseo_labs_google_keyword_overview`, `bulk_keyword_difficulty`).
- Bing visibility: bing-webmaster MCP.
- Behavior (only meaningful once real organic traffic exists): microsoft-clarity MCP.

## Relationship to the 3-agent blog pipeline

This playbook is the Research-phase lens for an existing page. For a new post, run the full pipeline (Research, Write, Review) in `CLAUDE.md`. For a ranking page: run Step 0 plus Parts 1 to 5 here, present the plan for approval, then apply the fixes and run the Phase 3 review agent against the pre-publish checklist before any publish or deploy.
