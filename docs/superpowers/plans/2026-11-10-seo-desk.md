# SEO Desk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app (`npm run seo-desk`, http://127.0.0.1:8766) that pulls every connected SEO source daily and opens on a plain-English Monday plan with standing, workable lists behind it.

**Architecture:** A dependency-free Node server under `seo-desk/`. Source modules pull through the MCP servers defined in `.mcp.json` (one shared stdio client) and from repo files, and write normalised snapshots to `seo-desk/data/` (gitignored). Pure rule modules turn snapshots into opportunities; lifecycle state lives in JSON files; a small API serves view models to a vanilla JS page.

**Tech Stack:** Node 22 ESM (`.mjs`), `node:http`, `node:test`, plain HTML/CSS/JS, hand-rolled SVG chart. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-10-seo-desk-design.md` (read it first; it wins on any conflict).

## Global Constraints

- No em or en dashes in any string a person reads (UI text, briefs, README). Plain spoken words.
- Never read `.env*`. Never print or log `.mcp.json` content; read only `mcpServers[key].command/args/env` to spawn a server.
- Nothing under `seo-desk/data/` is ever committed; test fixtures are synthetic (real shape, invented values and invented query strings).
- Server binds `127.0.0.1:8766` only and rejects requests whose `Host` is not `127.0.0.1:8766` or `localhost:8766`.
- Reuse, never copy: `scripts/lib/gsc-mcp.mjs` (`splitLines`, `parseLine`, `isResponse`), `scripts/lib/gsc-diagnose-core.mjs` (thresholds and detectors), `scripts/lib/change-log-core.mjs` (`windowsFor`, `metricsFor`, `controlFor`, `classify`, `WINDOW_DAYS`). Do not modify files under `scripts/`.
- Do not touch `src/pages/index.astro`, `src/pages/product.astro`, `src/components/common/StoryVideo.astro`.
- Click rate is computed at page level only. Site-wide average position is never a headline. DataForSEO keyword difficulty is never used.
- Every number shown carries its date range; every suggestion is labelled Hypothesis with its test; below a minimum-data gate the UI says "not enough data yet".
- Paid calls and scripts that write tracked files run only from a POST carrying `{confirm:true}`, after the UI has named the cost or the files.
- Workers do not commit, push, stash or switch branches. The orchestrator commits after verifying. Run `npx prettier --write` and `npx eslint` on the files you created only.
- Tests: `node --test seo-desk/tests/*.test.mjs` must pass; tests set `SEO_DESK_DATA` to a temp dir and never touch the network.

## Review Focus

1. A source fails or needs sign-in mid-refresh: the last good snapshot stays, the dot turns red or grey, the other sources still refresh. (Task 4 test)
2. First run with an empty data folder: every API route returns a valid payload with `empty:true` sections, no 500. (Task 7 test)
3. The plan file is missing, renamed or has a malformed table: `plan.error` is set and the week still builds from opportunities. (Task 3 and 6 tests)
4. Tiny numbers: a rule never emits below its gate, and percent changes with a base under 20 return `null` (rendered "not enough data yet"). (Task 5 test)
5. Refresh pressed twice, or the 06:00 job fires during a manual refresh: one run, the second call returns the running job. (Task 4 test)
6. The same page arriving as `https://simplescheduleai.com/blog/x`, `/blog/x/`, `/blog/x#h`: folded to `/blog/x` everywhere via `normPage`/`pathOf` from `gsc-diagnose-core.mjs`. (Task 2 test)

### Task 5: Opportunity rules and scoring

**Files:** Create `seo-desk/lib/rules.mjs`, `score.mjs`, `seo-desk/tests/rules.test.mjs`.

**Consumes:** shapes above; from `gsc-diagnose-core.mjs`: `nearPageOne`, `splitQueries`, `questions`, `unservedDemand`, `targetKeywords`, `pageMovement`, `groupByQuery`, `isBrand` and their thresholds (read that file for their exact inputs and outputs and adapt rows to them).

**Produces:** `detectAll(snaps, cfg) -> Opportunity[]` plus one exported detector per type; `score(opp, weights) -> {total: 0..100, parts:[{signal, weight, value, points, why}]}`; `rank(opps, weights) -> opps sorted with .score`.

Rules (each emits `measured`, `action`, `test` in plain words with numbers and the date range):

| type | emits when | isPageEdit |
| --- | --- | --- |
| near-page-one | non-brand query, position 8 to 20, impressions >= 30 in cur (reuse `nearPageOne`) | true |
| low-click-rate | page cur impressions >= 200, page position <= 15, page click rate < 0.5 x `EXPECTED_CTR[round(position)]` | true |
| competing-pages | reuse `splitQueries` (>= 2 pages, >= 30 impressions, top share < 0.7) | true |
| slipping | page prev impressions >= 50, page change <= -30%, and page change minus median page change <= -30 points | true |
| wrong-page | reuse `targetKeywords`: the ranking page differs from the registry page | true |
| unserved | reuse `unservedDemand` (>= 30 impressions, best position > 20), and no registry keyword equals the query | false |
| question | reuse `questions` (>= 6 words, >= 10 impressions, best position > 15) | true |
| needs-links | live page with fewer than 2 inbound pages, excluding `/` and legal pages | false |
| ai-gap | latest `aeo` money-keyword row with `ourPresent:false` and at least one competitor cited | false |
| engine-gap | query with Bing impressions >= 20 and no Google row, or Google impressions >= 30 and no Bing row for a money or pillar page | false |
| not-indexed | live page older than 14 days (`lastmod`) with `verdict:'not-indexed'` | false |

- [ ] Tests, one per rule, each with a firing row, a just-under-gate row that must not fire, and a brand query that must not fire where relevant; `low-click-rate` never uses query-level clicks; ids are stable across two runs; `score` parts sum to `total` and a `null` signal contributes 0 with `why` containing "not enough data"; with the `money-pages-first` preset an identical opportunity on `/pricing` outranks one on a blog post.
- [ ] Implement. Signals: `demand = min(1, log10(1+impressions)/3.5)`; `distance` per type (near-page-one: `(21 - position)/13`; low-click-rate: `1 - actual/expected`; slipping: `min(1, drop)`; others `0.5`); `importance` 1 money page, 0.7 pillar, 0.5 registry target, 0.3 other; `confidence = min(1, impressions/200)`, `null` under the type's gate; `effort` 0.9 title or link change, 0.6 section, 0.2 new post (higher means cheaper); `ai` 1 for ai-gap, 0.5 when the page appears in `aeo` cited URLs, else 0.

### Task 6: Lifecycle, freeze rule, verdicts, the week

**Files:** Create `seo-desk/lib/lifecycle.mjs`, `verdicts.mjs`, `week.mjs`, `brief.mjs`, `seo-desk/tests/week.test.mjs`.

**Produces:**

- `transition(item, action, {today, until, reason, text}) -> item`; actions `start`, `done`, `snooze`, `ignore`, `reopen`, `note`, `pin`, `unpin`. `snooze` needs a future `until` (default today + 7); `ignore` needs a reason; anything else from `ignored` except `reopen` and `note` throws `Error('conflict')`.
- `reconcile(items, detectedIds, today) -> items`: snoozed past its date becomes `new`; `done` and detected again more than 30 days after `doneAt` becomes `came-back`; ignored stays ignored; unseen ids get `new`.
- `frozenPages({items, opps, plan, edits, today}) -> Map<page, {until, since, why}>`: sources are (a) items with `status:'done'` whose opportunity `isPageEdit`, (b) plan `improve` rows with `done` and a `doneDate` or `judgeFrom`, (c) `edits` of kind `manual` (from `change-log-notes.jsonl`). `until = date + 28`. Routine git edits never freeze; `touchedOn(page, edits) -> [dates]` reports them for display.
- `eligibility(opp, frozen, today) -> {eligible:boolean, from: date|null}` (non page-edit opportunities are always eligible).
- `judgePage({page, changeDate, pageDaily, today}) -> {status:'too-early'|'judged', judgeFrom, before, after, control, verdict, clicksTooSmall}` built on `windowsFor`, `metricsFor`, `controlFor`, `classify` from `change-log-core.mjs`.
- `proposeTop5({plan, ranked, due, worries, openWork, frozen, items, today}) -> Card[]` following the five-slot recipe in the spec, skipping a slot that has nothing and filling from the next best eligible non page-edit opportunity; at most one card with `isPageEdit:true`.
- `worries({snaps, prevSnaps, sources, frozen}) -> [{id, kind, title, measured, fix}]` kinds: `dropped-from-index`, `slipping-page` (top three), `source-failed`, `crawl-issue`, `competitor-change`, `registry-fail`, `verdict-worse`.
- `waiting({verdictsDue, frozen, plan}) -> [{title, date}]`.
- `lockWeek(weekOf, cards)`, `getWeek(weekOf)`, `setTop5(weekOf, ids)`, `weeks()` in `state/weeks.json`.
- `brief(cardOrOpp, {frozen}) -> string`: page, measured line, suggested action, test date, and the repo rules: load `.claude/skills/seo-aeo-simplescheduleai.md` before editing a post, first command `npm run publish-gate <slug> -- --status`, one live-page edit a week and never the same page inside 28 days, tick the row in the plan file when the card came from the plan, log the edit with `npm run change-log`. No dashes.
