# SEO Desk Phase 3 (sidebar rebuild) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the SEO Desk's layout and look around a left sidebar and the standard SEO names so nothing is hidden, and add the performance overview, keyword map table, content gap cards, audit upgrades, AI visibility split, plan export, a Claude skill and retry logic.

**Architecture:** Same app. New back-end routes go in new files under `seo-desk/lib/api/ext/` (auto-loaded, matched before core routes). ## Global Constraints

- Everything in `.superpowers/sdd/2026-11-11-seo-desk-parity/context.md` and phase 1's `.superpowers/sdd/2026-11-10-seo-desk/context.md` still binds (no dashes in person-readable text, never read `.env*`, never print `.mcp.json`, nothing under `seo-desk/data/` in git, synthetic fixtures, 127.0.0.1 only, reuse not copy from `scripts/lib/`, do not modify `scripts/`, `docs/` or `src/`, page-level click rate only except the one whole-site figure, no site-wide average position, minimum-data gates on every percentage and share (the server sends them; pages never compute a percentage), confirm before anything that costs money or writes tracked files, the one-edit-a-week and 28-day rule read from `lib/lifecycle.mjs` and never re-implemented).
- **Names.** Labels use the standard terms exactly: Cannibalization, Runner-up keywords, Content gaps, Decay, Keyword map, Internal links, Low click rate, Wrong page ranking, Unanswered questions, Not indexed, Google and Bing differ. Each carries one plain sentence of explanation. "Click rate" and "position" are used; "CTR" and "SERP" are not.
- **Wording.** A recommendation is labelled a hypothesis and never states a cause as certain ("may", not "will").
- Route files: one new file per feature under `seo-desk/lib/api/ext/` exporting `routes`, built with `seo-desk/lib/api/kit.mjs`. Do not edit `seo-desk/lib/api.mjs`.
- File ownership is exclusive; a task edits only the files its "Files" line lists.
- The real desk runs under launchd on port 8766 with real data. Never stop it, never POST to it, never write to `seo-desk/data/`. Develop against a COPY of the data folder on your own port with `createServer({autoRefresh:false})`.
- Each back-end task writes its routes' response shapes to `.superpowers/sdd/2026-11-12-seo-desk-rebuild/api-<feature>.md`.
- Tests: `node --test seo-desk/tests/*.test.mjs` passes (506 at the start); logic is test-first; tests never touch the network.
- Workers commit their own task with explicit paths only; never `git add -A`, push, stash, reset or switch branches.

## Review Focus

1. A page reached by an old address (`#/opportunities`, `#/search`, `#/health`) after the rebuild: it still opens the right page; a bookmark never lands on a blank screen. (Task 3 test)
2. The theme switch: every colour comes from a variable; no text is unreadable in either theme; the choice survives a reload. (Task 3 check)
3. A sidebar count when its source has never been pulled or failed: it shows a dash, not 0, and the page says why. (Task 1 test)
4. A source that keeps failing: three retries, then it waits for the next morning; retries never overlap a running refresh. (Task 1 test)
5. Old audit runs saved before the severity change: they still open, with their old severities mapped to the new four. (Task 2 test)
6. The Claude skill asked something the desk cannot answer or while the desk is not running: it says so and gives the start command, and never invents numbers. (Task 5 check)

### Task 6: Ideas from the X posts (back end)

**Files:** Modify `seo-desk/lib/insights.mjs`, `seo-desk/lib/api/ext/insights.mjs`, `seo-desk/tests/insights.test.mjs`, `seo-desk/lib/audit/checks.mjs` (one new check only), `seo-desk/tests/audit.test.mjs`. **Produces:**

- Decay: each decaying page carries `dropKind: 'lost-rankings'|'lost-demand'|'lost-clicks'|'unclear'` and `dropKindLabel`, decided from the page's own numbers in the two periods (position worse by 2 or more places -> lost rankings; position within 1 place and views down 30 percent or more -> lost demand; position and views within 15 percent but clicks down 30 percent or more with at least 20 clicks before -> lost clicks at the same position; else unclear), reusing the signals in `scripts/lib/change-log-core.mjs` `classify` where they fit, and a `recommendation` per kind ("lost rankings": strengthen and link to the page; "lost demand": fewer people are searching, leave it; "lost clicks": look at the title and at what now sits above you). Each kind is labelled a hypothesis. `recentDrop: boolean` when the last 14 days have 30 percent fewer views than the 14 days before (both halves at least 50 views).
- Cannibalization: `choice` accepts `'leave-alone'`; each item carries `atRisk: {page, impressions, clicks}` (the weaker page's figures) and `likelyFalseAlarm: boolean` with `falseAlarmReason` (a brand search, or the two pages are a pillar and its own post). Items marked leave alone drop out of the sidebar count and the weekly proposal.
- `/api/week` adds `leaveAlone: [{page, reason, until}]`: frozen pages ("edited on 9 November, being measured until 7 December"), and cannibalization pages marked leave alone.
- `settings.planSize: 3 | 5` (default 5): the weekly proposal fills that many slots, keeping the recipe order.
- Lessons (`state/lessons.json`): `{id, text, status: 'trial'|'proven'|'dropped', verdictIds: [], createdOn, updatedOn}`; a lesson becomes `proven` when three linked verdicts read the same way and `dropped` when linked verdicts split, else `trial` (the founder can override). Routes: `GET /api/lessons`, `POST /api/lessons` `{text, verdictId?}`, `PUT /api/lessons/:id` `{text?, status?, addVerdictId?, removeVerdictId?}`, `DELETE /api/lessons/:id`. At most 200 lessons; text at most 300 characters.
- Audit: a new low-severity check `title-repeats-name`: the page title contains the same word of four or more letters three times, or the site name twice.

- [ ] Tests first for each rule above (each `dropKind` with a firing and a just-under case; halves under 50 views give `recentDrop: false`; a brand search is a likely false alarm; leave alone removes the item from the count; `planSize` 3 gives three cards in recipe order and never two page edits; a lesson goes trial -> proven on the third agreeing verdict and -> dropped on a split; the title check).
- [ ] Implement, write `api-lessons.md`, commit.

- Secondary keywords (from the second set of screenshots): `GET /api/insights/secondary-keywords`: `{term: 'Secondary keywords', explain: 'Searches a page already appears for but does not target.', count, items: [{id, page, query, impressions, position, targetKeyword (the page's own target), evidence, recommendation, test, state, eligibility, frozenUntil}]}`. An item exists when a live page that has a target keyword is shown 30 or more times in 28 days for a non-brand search that is not a target of any page, shares at least one meaningful word with the page's target or sits in the same topic, and is not the page's own target; at most three per page, ranked by views. `POST /api/insights/secondary-keywords/:id` `{action: 'adopt'|'done'|'dismiss'|'reopen'}`: adopt stores it in `state/targets.json` under a new list `secondary: [{keyword, page, addedOn}]` (never counted in the like-for-like position); the others use the item lifecycle. Working a secondary keyword into a page is a page edit, so the item carries eligibility from the lifecycle module.
- Keyword map table rows gain `source: ['file'|'search-console'|'import']`, `volume` (monthly searches when an import supplied one, else null; keyword difficulty is never stored or shown), `status: 'live'|'pending'` (live when `mappedTo` is a live page), and `clusterConflict: {page, keyword} | null` when an unmapped keyword falls in a topic that an existing page already targets, with the recommendation "Add this as a section on the existing page instead of writing a new one." Content gaps exclude searches with a cluster conflict (they are secondary keywords or sections, not new pages).
- `/api/nav` counts gain `secondaryKeywords`.

- [ ] Tests for the additions: a search under 30 views, a brand search, a search already targeted and the page's own target do not become secondary keywords; at most three per page; adopt writes the `secondary` list and never changes the like-for-like figure; a frozen page's item is not eligible; a cluster conflict is found for an unmapped keyword in a targeted topic and that keyword is not also a content gap; `volume` is null without an import and no row carries a difficulty field.
